# 연구 브리프

## 핵심 질문

신청서의 AI 발표 에이전트를 PWA로 구현할 때 어떤 아키텍처가 가장 현실적이며, Windows 발표 머신이 확장 디스플레이인 경우와 화면 복제인 경우 모두에서 공개 발표 화면과 비공개 Presenter Console을 안전하게 분리할 수 있는가?

## 신청서에서 확정된 요구

- PPTX/PDF, 현재 슬라이드, 스트리밍 STT를 결합한다.
- 확정 발화에서만 검색·RAG·LLM/VLM을 이벤트 기반으로 호출한다.
- `SUPPORTED` 카드만 청중 화면에 공개한다.
- 발표자 콘솔에는 코칭, 팀 메시지, 검색 진행 및 미검증 후보를 표시한다.
- 발화 후 5초 이내 최대 3개 자료 추천이 MVP 목표다.
- 내부 문서는 ACL 선필터, revision, anchor, content hash를 검증한다.
- 발표 후 이벤트를 재계산해 시간·속도·카드 이력 리포트를 만든다.

## 연구 축과 완료 기준

1. PWA 기반과 브라우저 제약: 설치성, 서비스 워커, 미디어 권한, 팝업·멀티스크린 API의 실제 지원 범위.
2. 확장 디스플레이: 사용자 제스처 한 번으로 발표 화면과 콘솔을 서로 다른 화면에 띄우는 안전한 흐름.
3. 복제 디스플레이: 발표 머신에는 공개 화면만, 개인 기기에는 콘솔만 띄우고 세션 상태를 저지연 동기화하는 흐름.
4. 실시간 백엔드: STT, 이벤트 오케스트레이션, 검색/RAG, 검증, 카드 상태 머신.
5. 보안·프라이버시: 공개/비공개 채널 분리, ACL, 세션 참가, 원본 음성·내부 문서 보호.
6. 프런트엔드/UX: 발표 중 인지부하, 장애 복구, 오프라인/불안정 네트워크, 접근성.
7. 기술 스택·배포·비용: MVP와 확장 단계의 선택.
8. 반론·검증: 브라우저 API 가용성, WebRTC 대 WebSocket, PWA만으로 가능한 범위의 공격적 검토.
