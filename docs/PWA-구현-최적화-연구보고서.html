1. 결론

PWA로 구현할 수 있다. 단, 공개 Stage와 Presenter Console을 보안상 분리하고, 자동 멀티스크린은 Chromium desktop의 향상 기능으로만 제공해야 한다. 기본 계약은 안내형 수동 설정이며, 화면 복제에서는 발표 머신에 Stage만 두고 개인 기기에 Console을 둔다.
확장 화면

자동 배치 + 정식 수동 폴백

Window Management API로 외부 디스플레이에 Stage를 배치한다. 미지원·권한 거부·팝업 차단 시 창 이동과 Stage 내부 fullscreen 클릭을 안내한다.

화면 복제

개인 기기 원격 Console

발표 PC에는 AudienceDisplaySession만 남긴다. 휴대폰/태블릿 Console은 account-authenticated pairing 후 WSS relay로 제어한다.

보수적 MVP: presenter-only evidence/coaching과 사전 승인 evidence library를 먼저 출시한다. Live web 결과는 private beta로 검증하고, precision·인지부하·관객 이해도를 통과한 뒤 공개한다.

2. 신청서의 제품 계약

  • PPTX/PDF와 notes를 업로드해 stable slide ID·version·anchor를 만든다.
  • 부분 STT는 자막·검색 예열만, 확정 STT는 검증 이벤트에 사용한다.
  • 내부 RAG는 ACL 선필터 + lexical/dense hybrid + revision/hash 검증이다.
  • Public Stage에는 검증되고 승인된 현재 카드만 표시한다.
  • 발표 후 immutable event를 재계산해 coaching/report를 만든다.
verdict     = PENDING | SUPPORTED | UNCERTAIN | CONFLICTING | UNSUPPORTED
publication = HIDDEN | AWAITING_APPROVAL | PUBLISHED | REJECTED
freshness   = CURRENT | STALE | SUPERSEDED

SUPPORTED는 공개됨이 아니라 공개 자격이 있음이다. 5초 목표는 사람의 승인까지가 아니라 eligible recommendation이 Console에 도착할 때까지다.

절대 약속하지 말 것: “PWA 설치 시 모든 Windows/browser에서 자동 이중 화면.” Window Management는 Baseline이 아니고, mirror는 별도 screen으로 보이지 않으며, fullscreen activation은 원격 전달되지 않는다.

5. 화면 복제 + 원격 Presenter Console

화면 복제에서 동일 PC에 Console을 띄우면 비공개 정보가 projector에도 나타난다. 발표 PC에는 Public Stage만 두고, Console은 다른 기기에서 실행한다.

  1. 기존 authenticated Console이 single-use `pair_id`(90초)를 만든다.
  2. QR은 권한이 없는 locator만 포함한다.
  3. 새 기기가 동일 계정 로그인 후 device key와 scope를 요청한다.
  4. 기존 Console이 기기명·계정·scope를 승인한다.
  5. 서버가 새 host-only DeviceSession을 발급하고 role-scoped WSS를 연다.
Transport결론이유
WebSocket/WSS채택TCP 443, 중앙 인증·revision·snapshot·receipt
WebRTC DataChannel후속ICE/TURN/signaling 필요, direct 보장 없음
WebTransport보류peer가 아니며 UDP 차단·성숙도 부담
BroadcastChannel원격 불가같은 origin/storage partition/device 범위

명령은 `commandId + controllerEpoch + baseRevision`을 가진다. gap은 snapshot으로 복구하고, offline 중 상대 명령(next/toggle)은 자동 replay하지 않는다. WSS 목표는 command→Stage p95 ≤300ms, reconnect→snapshot p95 ≤2s다.

6. 실시간 AI·RAG

업로드

MVP는 로컬 Python uploader, 이후 Cloud Run Python worker를 사용한다. python-pptx로 구조/notes, LibreOffice로 fidelity render, PyMuPDF로 PDF 좌표를 추출한다. OCR/VLM은 실패·복합 시각 슬라이드에만 사용한다.

7. 보안·개인정보·권리

Audience byte invariant

Audience HTTP/WSS/DOM/storage/SW/cache/log에는 PublishedAudienceCard 외의 private field가 없어야 한다.

Opaque sessions

Account·Control·Device·Display session을 분리하고 host-only HttpOnly cookie와 exact Origin 검사를 사용한다.

Audio minimization

browser mic permission과 consent를 분리한다. raw PCM은 메모리 retry ring만, transcript는 report 후 즉시 삭제를 기본으로 한다.

Executable rights

RightsRecord가 없는 asset은 공개하지 않는다. hash-bound approval, attribution, SSRF-safe fetch, 자체 CDN을 사용한다.

sibling subdomain은 서로 다른 origin이지만 same-site다. `SameSite=Strict`에만 의존하지 말고 synchronizer CSRF token, exact Origin, WSS Origin allowlist를 적용한다.

8. PWA UX

Prepare → Live → Review lifecycle IA를 사용한다. Console은 Now / Next / Signals만 빠르게 답해야 하고, Stage에는 app navigation이나 diagnostics가 없다.

Responsive Console

320px single-column, Now/Next/Signals bottom tabs, 44–48px live targets, stable control dock.

Failure clarity

Device offline, Server unreachable, Display disconnected를 분리하고 last sync·영향·복구 행동을 표시한다.

  • 본문 contrast 4.5:1, focus 3:1
  • 색만으로 상태를 구분하지 않음
  • routine sync는 status, stage-stop만 persistent alert
  • auto feed는 pause/stop/hide
  • 서비스 워커 update는 session 종료 후 활성화

10. Go / No-go 검증

  • Setup: Windows/browser/topology 30회 cold start, 90초 내 성공 ≥95%, private leak 0.
  • Chaos: Wi-Fi/WSS/phone lock/hotplug/fullscreen exit, recovery p95 <10s, duplicate 0.
  • Korean STT: 200 utterance에서 key entity/number/unit ≥95% 또는 오류 감지·억제.
  • Verification: 300 utterance blind labels, public-eligible precision ≥99%, false-support ≤1%.
  • Audience value: ≥60명 crossover에서 comprehension/calibration 개선, distraction 악화 없음.
  • Presenter load: ≥12명, 승인 때문에 delivery가 악화되지 않고 90% 이상 speech 중 처리.
  • Security: Audience byte capture private canary 0, stale/unauthorized publish 전부 거부.
  • Dress rehearsal: venue hardware/network 10회 연속 P0 failure 없음.
Kill rule: verification 또는 audience-value 실험이 실패하면 public live evidence만 중단한다. Presenter Copilot과 pre-approved Evidence Button은 유지한다.
